# 135 编辑器复制兼容机制 —— 逆向分析与官方规范对照

分析目标：`https://www.135editor.com/beautify_editor.html`
官方规范：`https://developers.weixin.qq.com/doc/service/guide/product/plugin_spec.html`
分析日期：2026-09-10

---

## 一、核心结论

**135 的技术路线是「给元素贴官方豁免标签，让公众号校验/转换引擎放行」，而不是「清除或改写样式」。**

这与我们此前的路线根本不同：

| 路线 | 做法 | 结果 |
|---|---|---|
| 我们（改造派） | 猜公众号要什么 → 把 `width:900px` 改成 `max-width:900px`、删掉 `justify`、删掉 `font-family` | 本地预览是我们的样子，公众号是作者原文 → **用户看到"不兼容"** |
| 135（豁免派） | 保留作者原文 → 贴 `data-ignore-width` 等官方豁免属性 | 公众号按作者的意图原样渲染 |

方法论：playwright 注入素材 → `window.current_editor.setContent()` → 读 `getContent()` 观察规范化结果。

## 二、官方规范依据（权威，已核实）

### 2.1 三个豁免属性（均属官方规范）

| 属性 | 规范条款 | 语义 | 生效范围 |
|---|---|---|---|
| `data-ignore-width` | **1.4.4** | 跳过 width 相关检测（居中布局不一致、溢出、宽度差异） | **节点 + 所有后代**（子树级，用 `closest()` 向上查） |
| `data-ignore-dm="low-contrast text-bg-gradient"` | **4.6** | 跳过指定 Dark Mode 规则检测 | ⚠️ **仅当前节点**，后代仍会被检测 |
| `data-no-dark` | **4.5.1** | 当前节点跳过算法转换 | ⚠️ **仅当前节点**，后代含内联样式仍会转换 |

`data-ignore-dm` 的可选值（空格分隔，可多个）：
- `low-contrast` —— 跳过「文字与背景对比度过低」检测
- `text-bg-gradient` —— 跳过「文字背景使用渐变」检测

官方原文示例：
```html
<!-- 该 section 及其内部所有子元素将跳过 width 违规检测 -->
<section data-ignore-width style="width: 800px;">…</section>

<!-- 该 section 将跳过 low-contrast、text-bg-gradient 违规检测 -->
<section data-ignore-dm="low-contrast text-bg-gradient">…</section>
```

### 2.2 ⚠️ 135 的自造属性（官方不认，不要学）

135 输出的这两个东西**在任何官方文档和官方算法里都不存在**：

| 135 的做法 | 证据 | 结论 |
|---|---|---|
| `data-darkmode-bgcolor` / `data-darkmode-color` / `data-darkmode-original-bgcolor` / `data-darkmode-original-color` / `data-darkmode-bgimage` | 官方规范与 `wechatjs/mp-darkmode` 算法源码均无此属性；算法**只读内联 `style`** | ❌ 第三方自造 |
| `<style type="text/css" class="darkmode">` | 官方 Dark Mode 是对内联样式运行的客户端算法，不读作者 `<style>`；且有资料指出微信会过滤 `<style>` | ❌ 会被过滤 |

另外社区已有明确教训：`alchaincyf/huasheng_editor#7` 专门提交"移除之前错误的 `data-darkmode-*` 属性方案"。

**→ 我们不要实现这两个。**

### 2.3 官方对 width 的完整规定（1.4）

三种违规场景：
| 问题 | 原因 |
|---|---|
| 居中布局不一致 | 设了固定宽度，屏幕比它宽时内容不再居中 |
| 存在溢出问题 | 左侧缩进过大 / 整体右偏 / 固定列宽超出容器 |
| 不同屏幕下宽度差异 | 固定宽度未自适应，占屏比例随屏幕变化 |

官方给出的违规示例是 `width: 586.438px`（带小数的浏览器计算值）和 `width: 500px`。
→ **注意：官方判违规看的是"实际渲染是否溢出/居中不一致"，不是"写了 px 就违规"。** 这正是 `data-ignore-width` 存在的意义。

图片宽度检测（官方原文）：
> 优先等待图片加载，用 `naturalWidth`；超时则按 `img.style.width` → `data-w` → `width` 属性 fallback；都没有则塞 1×1 透明 SVG 兜底。
> **建议给 `<img>` 添加 `data-w` 属性。**

→ 我们已经实现了 `data-w`（`normaliseWechatTree` 里从 `sourceDoc.images` 取 `naturalWidth`），这条是对的，保留。

### 2.4 text-align（1.6）

官方原文只禁 **`start` / `end`**：
> 设置 `text-align` 为 `start，end`
> 不同终端对 `start` 值兼容性存在差异，造成部分设备文字居中、部分设备文字居左的不一致体验。

**规范中完全没有提及 `justify`。**

→ 我们此前把 `justify` 也一并删除是**过度处理**。135 的选择是原样保留 + 镜像 `align` 属性。

### 2.5 font-family（第 3 章）

官方措辞是"**不建议**"而非"禁止"：
> 不建议设置任何字体族。公众号已设定一套经过充分优化的默认字体栈……任何自定义字体设置都可能破坏此一致性。

并给出了具体的兼容性问题：iOS 17+ 部分版本因分别映射到 `system-ui` 和 `PingFang SC` 的同一字体不同版本，导致文字大小与字间距差异明显。

→ 这条我们移除 `font-family` 是**有官方依据的**，保留该行为。

### 2.6 !important（4.5.2）

> 无论何种场景，平台均不建议创作者在排版时使用 `!important`，这会使平台添加的公共样式失效，同时 Dark Mode 算法也需搭配 `!important` 来实现样式覆盖。

→ 这条我们移除 `!important` 也是**有依据的**，保留该行为。

### 2.7 Dark Mode 总原则（第 4 章）

> 算法秉承**尽可能保留原文信息**的原则（颜色亦为信息的一种，算法不会将红色转为橙色），仅当信息在 Dark Mode 下**难以辨识**（对比度不足）或**视觉不适**（亮度过高）时才进行调整。

相关条款：
- 4.1.1 使用对比度适中的颜色（算法会平衡调整过低/过高对比度）
- 4.1.2 文字背景尽量不要使用渐变（有文字时算法会 mix 转纯色再转换）
- 4.1.3 纯背景可以使用渐变（上方无文字，算法不处理）
- 4.4 SVG 不处理，建议 `stroke="currentColor" fill="currentColor"`

## 三、135 实测规则集

### 规则 1：固定像素宽度 → 保留 + `data-ignore-width` + `box-sizing`
实测 100 / 320 / 375 / 400 / 500 / 677px **全部**加豁免，**无阈值**。
```html
<!-- 输入 -->
<section style="width:600px;margin:0 auto;">
<!-- 输出 -->
<section style="width:600px;margin:0 auto;box-sizing:border-box;" data-ignore-width>
```

### 规则 2：非 px 宽度 → 镜像 `max-width !important`
```html
<!-- width:60% -->
<section style="width:60%;box-sizing:border-box;max-width:60% !important;">
<!-- width:calc(100% - 20px) -->
<section style="width:calc(100% - 20px);box-sizing:border-box;max-width:calc(100% - 20px) !important;" data-ignore-width>
```
→ 用 `max-width !important` 兜底防溢出（注意这条用 `!important` 是**它自己的选择**，与官方"不建议"相悖，但确实能压住溢出）。

### 规则 3：渐变背景 → `data-ignore-dm="low-contrast"`
```html
<section style="background:linear-gradient(90deg,#faa,#afa);box-sizing:border-box;" data-ignore-dm="low-contrast">
```
并且**低对比度文字节点也会单独贴**（因为它做了对比度计算）：
```html
<section style="background:linear-gradient(...);" data-ignore-dm="low-contrast">
  文字：<span style="color:#444;" data-ignore-dm="low-contrast">深灰字</span>
</section>
```
→ 父子都贴，正是因为**官方 `data-ignore-dm` 只对当前节点生效**。

### 规则 4：`text-align` 不动，镜像 `align` 属性
```html
<p style="text-align:justify;" align="justify">…</p>
```
`justify` / `start` / `end` / `left` / `inter-word` 全部原样保留。

### 规则 5：`box-sizing: border-box` 普惠
几乎所有输出元素都补 `box-sizing:border-box`，保证 `width` 语义一致。

### 规则 6：容器与标签规范化
| 输入 | 输出 |
|---|---|
| `<div>` | `<section>` |
| `<span>`（独立） | `<p>` |
| `<dl><dt><dd>` | `<ul><li><p>` |
| `<ul><li>` | `<ul class="list-paddingleft-2" style="margin:0px;padding:0 0 0 30px;list-style-position:outside;"><li><p>` |
| `<table>` | `<table width="100%"><tbody><tr class="firstRow">` |
| `<h2>` | `<h2 style="font-size:17px;">` |
| `<img>` | 包进 `<p>`，加 `vertical-align:baseline` |
| `<i>` | `<em>` |
| 空 `<p>` | `<p><br/></p>` |
| `main`/`article`/`aside`/`header`/`footer`/`nav`/`figure`/`center` | **原样保留** |

**`class` 属性被保留**（`class="quote"` / `class="rule"`）—— 我们此前是全剥离的。

### 规则 7：`transform` 补全厂商前缀
```html
<!-- 输入 -->
<section style="transform:rotate(5deg);">
<!-- 输出 -->
<section style="transform: rotate(5deg);-webkit-transform: rotate(5deg);-moz-transform: rotate(5deg);-o-transform: rotate(5deg);">
```

### 原样放过（不做处理）
`position:absolute` / `box-shadow` / `filter` / `opacity` / `display:flex` / `display:grid` / `font-family` / `!important` / 空 `<p>` / 空 `<section>`

## 四、135 的复制链路实现

源码：`/js/categories/beautify_editor/copy_editor_content.js`

```js
function copyEditorContent() {
  var editorHtml = getEditorHtml();

  function writeClipboardData(event) {
    event.clipboardData.setData("text/html", editorHtml);
    event.preventDefault();
  }

  document.addEventListener("copy", writeClipboardData);
  if (!document.execCommand("copy")) throw new Error("rejected");
  ...
  finally { document.removeEventListener("copy", writeClipboardData); }
}
```

要点：
1. 拦截 `document` 的 `copy` 事件，用 `clipboardData.setData('text/html', html)` 写入
2. 用 `document.execCommand('copy')` 触发（需用户手势）
3. **复制前几乎不清洗** —— `getEditorHtml()` 只做了一件事：空 `<p>` 补 `<br/>`

```js
// getEditorHtml 逻辑（还原后）
$(current_editor.document.body).find("p").each(function () {
  if ($(this).find("br").length === 0) {
    if ($.trim(strip_tags($(this).html())) === " ") $(this).html("<br/>");
    else if ($.trim(strip_tags($(this).html())) === "" && this.tagName !== "SPAN") $(this).remove();
  }
});
```

→ **真正的工作在"内容进入编辑器"时就完成了，复制只是搬运。**

## 五、我们的问题诊断

| 我们的行为 | 官方依据 | 135 的行为 | 判定 |
|---|---|---|---|
| `width:900px` → `width:auto;max-width:900px` | 无（扭曲作者意图） | 保留 + `data-ignore-width` | ❌ **必须改** |
| 删除 `justify` | 无（1.6 只禁 start/end） | 保留 + `align="justify"` | ❌ **必须改** |
| 移除 `font-family` | ✅ 第 3 章"不建议" | 保留 | ✅ 保留我们的行为 |
| 移除 `!important` | ✅ 4.5.2"不建议" | 保留 | ✅ 保留我们的行为 |
| 剥离 `class` | 无 | 保留 | ⚠️ 可考虑保留 |
| 记 `data-w` | ✅ 官方建议 | 也做 | ✅ 保留 |
| 空 `<p>` 补 `<br/>` | — | 也做 | ✅ 保留 |
| div → section | — | 也做 | ✅ 保留 |
| 渐变仅提示 | 4.6 可豁免 | 加 `data-ignore-dm` | ❌ 应自动加豁免 |
| 无 `box-sizing` | — | 普惠补齐 | ❌ 应补 |
| 无 `align` 镜像 | — | 补 | ⚠️ 可选 |

**根本问题：我们把"作者想要的样式"改成了"我们以为安全的样式"。**

## 六、改造方案

### 6.1 必须改（消除"不兼容"观感）

1. **固定 px 宽度不再改写**，改为保留 + 追加 `data-ignore-width`
2. **`justify` 不再删除**（保留 `start`/`end` 的原转换行为，因为官方明确禁）
3. **渐变背景自动追加 `data-ignore-dm="low-contrast text-bg-gradient"`**
4. **低对比度文字节点自动追加 `data-ignore-dm="low-contrast"`**（需实现对比度计算）
5. **普惠补 `box-sizing:border-box`**
6. **`rewriteResponsiveLayout` 的宽度改写与 margin 归零逻辑应移除**（破坏原样）

### 6.2 考虑改

7. `class` 属性保留（不剥离）
8. `text-align` 值镜像到 `align` 属性
9. `max-width` 镜像为 `max-width: X !important`
10. `transform` 补全厂商前缀

### 6.3 明确不做

11. ❌ `data-darkmode-*` 五件套 —— 官方不认
12. ❌ `<style class="darkmode">` —— 会被过滤

### 6.4 保留现有正确能力
- div/main/article → section
- 空 `<p>` 补 `<br/>`
- 图片 `data-w` + `max-width:100%`
- 移除 `font-family` / `!important`（有官方依据）
- SVG 点击事件补 `click`

### 6.5 豁免属性的生效范围（实现要点）

```
data-ignore-width        → 子树级：用 closest('[data-ignore-width]') 判断
data-ignore-dm           → 仅当前节点：只判断该元素自身
data-no-dark             → 仅当前节点：只判断该元素自身
```

⚠️ 这是关键差异。`data-ignore-dm` 若按子树级实现，会**漏掉祖先已豁免但子节点仍需检测**的情况，也会错误地让子节点的其他违规被静默。

同时：`data-ignore-dm` 的值要**合并**（空格分隔），不要覆盖。
